# SecondServe

> **A Sustainable Near-Expiry Product Sharing Platform**  
> **แพลตฟอร์มส่งต่อสินค้าใกล้หมดอายุเพื่อการบริโภคอย่างยั่งยืน**  
> **More Than an Expiry Date. | คุณค่ามีมากกว่าวันหมดอายุ**  
> **Project Specification / Startup MVP / Web Application**

---

## ภาพรวมโครงการ

**SecondServe** เป็น Web Application สำหรับรวบรวม แสดง ค้นหา และจัดการสินค้าใกล้หมดอายุ จากร้านของชำและร้านค้าปลีกขนาดเล็ก โดยเชื่อมโยงร้านค้า ผู้บริโภค และไรเดอร์ผู้จัดส่งสินค้าเข้าด้วยกันผ่านระบบออนไลน์ 

ผู้บริโภคสามารถค้นหาสินค้า ดูรายละเอียด ราคา ส่วนลด จำนวนคงเหลือ และวันหมดอายุ พร้อมเลือกได้ว่าจะเดินทางไปรับสินค้าที่ร้านด้วยตนเอง (Self-Pickup) หรือใช้บริการจัดส่งถึงที่โดยไรเดอร์ (Rider Delivery) ขณะที่ร้านค้าสามารถจัดการสต็อกสินค้าและคำสั่งซื้อได้อย่างเป็นระบบ และไรเดอร์สามารถสร้างรายได้เสริมจากการรับงานจัดส่งสินค้าในพื้นที่ใกล้เคียง

แนวคิดของ SecondServe คือการเพิ่มโอกาสให้สินค้าใกล้หมดอายุถูกนำไปใช้ประโยชน์แทนการถูกทิ้ง ช่วยให้ร้านค้ามีโอกาสจำหน่ายสินค้าที่เหลือ ลดการสูญเสียทรัพยากร (Food Waste) และทำให้ผู้บริโภคเข้าถึงสินค้าราคาประหยัดได้อย่างสะดวกรวดเร็ว

โครงการใช้เทคโนโลยี **Next.js**, **Tailwind CSS**, **Supabase (PostgreSQL, Auth, Storage, RLS)**, **GitHub** และ **Vercel** โดยพัฒนาเป็น Web Application เพื่อให้เหมาะกับขอบเขตของโครงงานและสามารถพัฒนาเป็น Startup MVP ได้จริง

## 1. ปัญหาที่ Project ต้องการแก้

สินค้าใกล้หมดอายุจำนวนมากยังอยู่ในสภาพสมบูรณ์และปลอดภัยต่อการบริโภคหรือใช้งาน แต่หากร้านค้าไม่สามารถจำหน่ายได้ทัน สินค้าจะกลายเป็นขยะของเสีย ส่งผลให้ร้านค้าสูญเสียต้นทุนและรายได้ ขณะเดียวกันผู้บริโภคไม่สามารถทราบได้อย่างสะดวกว่าร้านค้าใกล้ตัวมีสินค้าลดราคาอะไรบ้าง และในหลายกรณีผู้บริโภคไม่สะดวกเดินทางไปรับสินค้าที่ร้านด้วยตนเอง

#### ปัญหาของผู้บริโภค
- ไม่ทราบว่าร้านค้าใกล้ตัวมีสินค้าใกล้หมดอายุรายการใดบ้าง
- ต้องค้นหาสินค้าจากหลายร้านด้วยตนเอง ขาดศูนย์กลางข้อมูล
- ไม่สามารถดูราคาและส่วนลดของสินค้าได้จากที่เดียว
- ไม่ทราบจำนวนสินค้าคงเหลือและช่วงเวลาเปิด-ปิดร้านที่ชัดเจน
- ไม่สะดวกเดินทางไปรับสินค้าที่ร้านในเวลาที่จำกัด ขาดตัวเลือกบริการจัดส่ง
- ขาดช่องทางติดตามสถานะรายการซื้อหรือการจัดส่งอย่างเป็นระบบ

#### ปัญหาของร้านค้า
- สินค้าใกล้หมดอายุขายไม่ทันก่อนถึงวันหมดอายุ กลายเป็นต้นทุนสูญเปล่า
- ขาดช่องทางออนไลน์เฉพาะสำหรับเร่งจำหน่ายสินค้ากลุ่มนี้
- การจัดการข้อมูลสินค้า ราคา จำนวน และวันหมดอายุยังไม่เป็นระบบ
- การรับรายการซื้อผ่านหลายช่องทางทำให้เกิดความสับสนและสินค้าชนกัน
- ไม่มีระบบจัดส่งสินค้าของตนเอง ทำให้จำกัดเฉพาะลูกค้าที่เดินมาหน้าร้าน

#### ปัญหาของผู้ส่งสินค้า (Rider)
- ต้องการโอกาสสร้างรายได้เสริมที่มีความยืดหยุ่นในพื้นที่ใกล้เคียง
- ขาดแพลตฟอร์มที่เชื่อมโยงงานจัดส่งสินค้าอุปโภคบริโภคและของชำในระดับชุมชน

## 2. Value Proposition

#### สำหรับผู้บริโภค (Consumer)
- ค้นหาสินค้าใกล้หมดอายุและสินค้าราคาพิเศษจากหลายร้านค้าได้ในแพลตฟอร์มเดียว
- ดูราคา ส่วนลด จำนวนสินค้า และวันหมดอายุได้อย่างโปร่งใส ชัดเจน
- มีความสะดวกสบายด้วยตัวเลือกทั้งการไปรับสินค้าที่ร้าน (Self-Pickup) หรือสั่งให้ไรเดอร์จัดส่งถึงบ้าน (Delivery)
- ติดตามสถานะคำสั่งซื้อและตำแหน่งการจัดส่งของไรเดอร์ได้แบบ Real-time
- ประหยัดค่าใช้จ่ายในชีวิตประจำวัน พร้อมมีส่วนร่วมในการบริโภคอย่างยั่งยืน

#### สำหรับร้านค้า (Store)
- เพิ่มโอกาสจำหน่ายสินค้าใกล้หมดอายุก่อนกลายเป็นของเสีย เปลี่ยนสินค้าเหลือทิ้งเป็นรายได้
- มีช่องทางออนไลน์เฉพาะสำหรับนำเสนอสินค้าและโปรโมชั่นแบบเร่งด่วน
- ขยายฐานลูกค้าได้กว้างขึ้นด้วยบริการจัดส่งผ่านเครือข่ายไรเดอร์ โดยร้านค้าไม่ต้องมีทีมส่งของเอง
- จัดการข้อมูลสินค้า สต็อก ราคา วันหมดอายุ และรายการสั่งซื้อผ่านระบบเดียว
- สามารถส่งต่อสินค้าที่ไม่สามารถจำหน่ายได้ให้แก่องค์กรการกุศลหรือผู้ต้องการความช่วยเหลือ

#### สำหรับไรเดอร์ (Rider)
- สร้างรายได้เสริมจากการรับงานจัดส่งสินค้าในพื้นที่ใกล้เคียง
- กำหนดเวลาการทำงานได้อย่างอิสระและยืดหยุ่นตามความสะดวก
- อัตราค่าจัดส่งที่เป็นธรรมและโปร่งใสตามระยะทางจริง
- มีส่วนร่วมในภารกิจลด Food Waste และช่วยส่งต่อสินค้าคุณภาพดีสู่ผู้บริโภคได้อย่างรวดเร็ว

> **คุณค่าหลัก:** เชื่อมโยงร้านค้า ผู้บริโภค และไรเดอร์ เพื่อสร้างระบบนิเวศการส่งต่อสินค้าใกล้หมดอายุให้เกิดประโยชน์สูงสุด รวดเร็ว และยั่งยืน

## 3. กลุ่มผู้ใช้งาน (4 User Roles)

ระบบ SecondServe กำหนดบทบาทผู้ใช้งานออกเป็น **4 บทบาทหลัก (4 User Roles)** เพื่อรองรับกระบวนการทำงานที่ครอบคลุม:

### 3.1 ผู้บริโภค (`consumer`)
- สมัครสมาชิก ยืนยันตัวตน และเข้าสู่ระบบ
- ค้นหาและกรองสินค้าตามชื่อ หมวดหมู่ ราคา ร้านค้า พิกัดระยะทาง และส่วนลด
- ดูรายละเอียดสินค้า ราคาปกติ ราคาพิเศษ จำนวนคงเหลือ และวันหมดอายุ
- เลือกสินค้าใส่ตะกร้าและทำรายการสั่งซื้อ
- เลือกวิธีรับสินค้า:
  - **รับเองที่ร้าน (Self-Pickup)**: แสดงเวลาและแผนที่ร้านค้าเพื่อไปรับสินค้า
  - **จัดส่งโดยไรเดอร์ (Rider Delivery)**: ระบุที่อยู่จัดส่งและคำนวณค่าส่งตามระยะทาง
- ชำระเงินและติดตามสถานะคำสั่งซื้อ
- ติดตามสถานะการจัดส่งและพิกัดของไรเดอร์
- ตรวจสอบประวัติการสั่งซื้อย้อนหลัง
- รีวิวและให้คะแนนร้านค้าและไรเดอร์ผู้จัดส่ง

### 3.2 ร้านค้า (`store`)
- ลงทะเบียนร้านค้าและจัดการข้อมูลโปรไฟล์ร้าน (ชื่อ, ที่อยู่, พิกัด, เวลาเปิด-ปิด, ภาพถ่ายร้าน)
- เพิ่ม แก้ไข และจัดการสินค้าใกล้หมดอายุ (ชื่อ, หมวดหมู่, ราคาปกติ, ราคาลด, จำนวน, วันหมดอายุ, ภาพสินค้า)
- เปิดหรือปิดสถานะการขายของสินค้าแต่ละรายการ
- ตรวจสอบรายการสั่งซื้อที่เข้ามาในระบบ
- กดยืนยันออเดอร์และเตรียมสินค้า (พร้อมระบุเมื่อสินค้าพร้อมให้ลูกค้ามารับ หรือพร้อมให้ไรเดอร์มารับ)
- ส่งมอบสินค้าให้ลูกค้าหน้าร้าน หรือส่งมอบให้ไรเดอร์พร้อมตรวจสอบความถูกต้อง
- จัดการสินค้าที่ไม่สามารถจำหน่ายได้เพื่อส่งต่อ (Donation/Sharing)

### 3.3 ผู้ส่งสินค้า / ไรเดอร์ (`rider`)
- ลงทะเบียนสมัครเป็นไรเดอร์ และบันทึกข้อมูลยานพาหนะ (ประเภทยานพาหนะ, ป้ายทะเบียน, เบอร์โทรศัพท์)
- เปิด/ปิดสถานะพร้อมรับงาน (Online / Offline)
- ตรวจสอบรายการคำสั่งซื้อที่ต้องการการจัดส่งในบริเวณใกล้เคียง (Delivery Job Pool)
- กดรับงานจัดส่งสินค้า (Accept Delivery Job)
- ดูรายละเอียดเส้นทาง นำทางไปยังร้านค้าเพื่อรับสินค้า (Store Location)
- ตรวจสอบสินค้าและกดยืนยันการรับสินค้าจากร้านค้า (Picked Up)
- นำทางไปยังที่อยู่ของผู้บริโภคเพื่อจัดส่ง (Customer Delivery Address)
- ส่งมอบสินค้าและกดยืนยันการจัดส่งสำเร็จ (Proof of Delivery / Delivered)
- ตรวจสอบประวัติการจัดส่งและสรุปรายได้ค่ารอบการจัดส่ง

### 3.4 ผู้ดูแลระบบ (`admin`)
- ตรวจสอบ อนุมัติ หรือระงับบัญชีผู้ใช้งาน ร้านค้า และไรเดอร์
- ตรวจสอบข้อมูลสินค้า เนื้อหาที่เผยแพร่ และความถูกต้องของรายการ
- กำหนดและจัดการหมวดหมู่สินค้าในระบบ
- กำหนดโครงสร้างและอัตราค่าจัดส่งพื้นฐาน
- ตรวจสอบข้อพิพาทหรือปัญหาการสั่งซื้อและการจัดส่ง
- ตรวจสอบ Dashboard ภาพรวมสถิติ ผู้ใช้งาน ยอดคำสั่งซื้อ และปริมาณสินค้าที่ช่วยลดขยะอาหารได้

## 4. ฟังก์ชันหลักของ Startup MVP

### 4.1 Landing / Home Page
- แนะนำแนวคิด แบรนด์ และคุณค่าของ SecondServe
- แสดงรายการสินค้าใกล้หมดอายุ Flash Sale / สินค้าแนะนำรอบตัว
- หมวดหมู่สินค้า (เบเกอรี่, ผักผลไม้, อาหารพร้อมทาน, ของแห้ง, เครื่องดื่ม ฯลฯ)
- แสดงรายชื่อร้านค้าพาร์ทเนอร์ที่เข้าร่วมโครงการ
- ช่องทางค้นหาด่วนตามพิกัดและหมวดหมู่
- เมนูและปุ่มเข้าสู่ระบบ / สมัครสมาชิกสำหรับทุกบทบาท (Consumer, Store, Rider)

### 4.2 Authentication & Role-Based Access Control
- ระบบสมัครสมาชิกและเข้าสู่ระบบผ่าน Supabase Auth
- กำหนดสิทธิ์และบทบาทผู้ใช้งานชัดเจน 4 กลุ่ม: `consumer`, `store`, `rider`, `admin`
- ระบบตรวจสอบ Session และคุ้มครองหน้าเว็บตามสิทธิ์ (Protected Routes)
- การจัดการข้อมูลโปรไฟล์เฉพาะของแต่ละบทบาท

### 4.3 Store Profile Management
- จัดการชื่อร้าน รายละเอียดร้าน ที่อยู่ และเบอร์โทรติดต่อ
- กำหนดพิกัดละติจูดและลองจิจูด (Latitude & Longitude) สำหรับคำนวณระยะทาง
- จัดการเวลาเปิด-ปิดร้านค้า
- อัปโหลดและจัดการภาพหน้าร้านค้าผ่าน Supabase Storage
- สถานะร้านค้า: `pending`, `active`, `closed`, `suspended`

### 4.4 Product Management
- ฟอร์มเพิ่ม/แก้ไขข้อมูลสินค้าใกล้หมดอายุ
- ระบุชื่อ รายละเอียด หมวดหมู่ ราคาปกติ ราคาพิเศษ และจำนวนคงเหลือ
- ระบุวันหมดอายุ (Expiry Date) พร้อมระบบคำนวณระยะเวลาคงเหลือก่อนหมดอายุ
- อัปโหลดรูปภาพสินค้าจัดเก็บใน Supabase Storage
- จัดการสถานะสินค้า: `active`, `sold_out`, `expired`, `shared`

### 4.5 Search and Filter System
- ค้นหาตามชื่อสินค้าและชื่อร้านค้า
- กรองตามหมวดหมู่สินค้า
- กรองตามระยะทางหรือพื้นที่ใกล้ตัว (Distance-based filtering)
- กรองตามช่วงราคาและระดับส่วนลด (%)
- กรองตามวันหมดอายุ (เช่น หมดอายุภายในวันนี้, ภายใน 3 วัน)
- กรองเฉพาะสินค้าที่มีสถานะพร้อมจำหน่ายและมีจำนวนคงเหลือ > 0

### 4.6 Order / Reservation System
- ผู้บริโภคเลือกสินค้าและจำนวนที่ต้องการ
- ระบบตรวจสอบสต็อกสินค้าแบบ Real-time ก่อนทำรายการ
- **ตัวเลือกรูปแบบการรับสินค้า (Fulfillment Options):**
  - **Self-Pickup (รับเองที่ร้าน):** ไม่คิดค่าส่ง แสดงเวลาที่ร้านค้าพร้อมให้รับสินค้า
  - **Rider Delivery (จัดส่งถึงที่):** ระบุที่อยู่จัดส่ง คำนวณค่าส่งตามระยะทาง
- คำนวณยอดรวมสุทธิ (ราคาสินค้ารวม + ค่าบริการจัดส่ง)
- สร้างคำสั่งซื้อ (Order) ในสถานะ `pending`
- ร้านค้าตรวจสอบและกดยืนยันออเดอร์ (`confirmed` / `preparing`)
- เมื่อเตรียมสินค้าเสร็จ อัปเดตสถานะเป็น `ready_for_pickup`

### 4.7 Delivery System (ระบบจัดส่งสินค้า)
- **Job Pool สำหรับไรเดอร์:** คำสั่งซื้อประเภท Delivery ที่ร้านค้าเตรียมเสร็จจะแสดงใน Pool งานของไรเดอร์ในพื้นที่
- **การรับงาน (Accept Job):** ไรเดอร์ที่พร้อมรับงานกดรับออเดอร์ สถานะเปลี่ยนเป็น `rider_assigned`
- **การรับสินค้า (Pickup Stage):** ไรเดอร์เดินทางไปร้านค้า ร้านค้าส่งมอบสินค้า ไรเดอร์ตรวจสอบความถูกต้องและกดยืนยันเป็น `picked_up`
- **การจัดส่ง (Delivery Stage):** ไรเดอร์เดินทางไปที่อยู่จัดส่ง สถานะเปลี่ยนเป็น `delivering`
- **การส่งมอบสำเร็จ (Completed Delivery):** ไรเดอร์ส่งมอบสินค้าแก่ผู้บริโภค พร้อมถ่ายภาพยืนยัน/กดยืนยัน สถานะเปลี่ยนเป็น `delivered` และ Order ปรับเป็น `completed`
- **การยกเลิก/กรณีฉุกเฉิน:** ระบบรองรับการยกเลิกและแจ้งเตือนไปยังผู้เกี่ยวข้อง

### 4.8 Sharing / Donation System (ระบบส่งต่อสินค้า)
- ร้านค้าสามารถเลือกสินค้าใกล้หมดอายุที่ไม่สามารถจำหน่ายได้ทันเพื่อนำไปบริจาค/ส่งต่อ
- ระบุประเภทการส่งต่อและบันทึกข้อมูล
- ปรับสถานะสินค้าเป็น `shared` หรือ `donated`
- เป็นฟังก์ชันส่งเสริมความยั่งยืนของ MVP

### 4.9 Dashboard แยกตาม 4 บทบาท
- **Dashboard ผู้บริโภค (`consumer`):** รายการที่รอยืนยัน, รายการที่กำลังเตรียม, รายการที่กำลังจัดส่ง/พร้อมรับ, ประวัติการสั่งซื้อ, ยอดเงินที่ประหยัดได้
- **Dashboard ร้านค้า (`store`):** สรุปยอดขาย, ออเดอร์ที่เข้ามา, ออเดอร์ที่รอไรเดอร์มารับ, สินค้าใกล้หมดอายุที่ต้องเร่งขาย, สินค้าที่ขายหมดแล้ว
- **Dashboard ไรเดอร์ (`rider`):** งานที่เปิดรับในรัศมีใกล้เคียง, งานที่กำลังดำเนินการจัดส่ง, ประวัติงานจัดส่งสำเร็จ, สรุปรายได้สะสม
- **Dashboard ผู้ดูแลระบบ (`admin`):** ภาพรวมผู้ใช้งาน 4 กลุ่ม, จำนวนร้านค้า, จำนวนไรเดอร์, ปริมาณสินค้าและอาหารที่ช่วยลดการสูญเสีย, ภาพรวมธุรกรรม

## 6. ความสัมพันธ์ของฐานข้อมูล (Database Relationships)

เนื่องจาก Supabase ใช้ฐานข้อมูลเชิงสัมพันธ์ **PostgreSQL** จึงสามารถกำหนดความสัมพันธ์ของข้อมูลผ่าน **Foreign Key (FK)** ได้อย่างสมบูรณ์ แม่นยำ และรองรับความถูกต้องของข้อมูล (Data Integrity):

```
                        ┌───────────────────────────────┐
                        │         users (Table)         │
                        │ id (PK) | role (4 roles)      │
                        └───────┬───────────────┬───────┘
                                │ 1:1           │ 1:1
              ┌─────────────────┴─────┐   ┌─────┴─────────────────┐
              │     stores (Table)    │   │     riders (Table)    │
              │ id (PK)               │   │ id (PK -> users.id)   │
              │ ownerId (FK->users.id)│   │ status, vehicleType   │
              └─────────┬─────────────┘   └───────────┬───────────┘
                        │ 1:N                         │
                        ▼                             │
              ┌───────────────────┐                   │
              │  products (Table) │                   │
              │ id (PK)           │                   │
              │ storeId (FK)      │                   │
              └─────────┬─────────┘                   │
                        │                             │
                        ▼                             ▼
              ┌───────────────────────────────────────────────┐
              │                 orders (Table)                │
              │ id (PK)                                       │
              │ userId   (FK -> users.id)                     │
              │ storeId  (FK -> stores.id)                    │
              │ riderId  (FK -> riders.id, nullable)          │
              │ items (FK ref products)                       │
              │ deliveryType: 'pickup' | 'delivery'           │
              │ status: pending..delivering..completed        │
              └───────────────────────┬───────────────────────┘
                                      │
                        ┌─────────────┴─────────────┐
                        ▼                           ▼
              ┌───────────────────┐       ┌───────────────────┐
              │   shares (Table)  │       │  reviews (Table)  │
              │ storeId + prodId  │       │ userId + storeId  │
              │                   │       │ + riderId + order │
              └───────────────────┘       └───────────────────┘
```

- **`users` -> `stores`**: ร้านค้า 1 ร้านผูกกับบัญชีผู้ใช้เจ้าของร้าน (`stores.ownerId` -> `users.id`)
- **`users` -> `riders`**: ไรเดอร์ 1 คนผูกกับบัญชีผู้ใช้ที่เป็นไรเดอร์ (`riders.id` -> `users.id`)
- **`stores` -> `products`**: ร้านค้า 1 ร้านมีสินค้าได้หลายรายการ (`products.storeId` -> `stores.id`)
- **`orders`**: เชื่อมโยง 3 ฝ่ายหลัก ได้แก่ ผู้บริโภค (`userId`), ร้านค้า (`storeId`), และไรเดอร์ที่รับงานจัดส่ง (`riderId`)
- **`shares`**: บันทึกการส่งต่อสินค้าจากร้านค้า (`storeId` และ `productId`)
- **`reviews`**: เชื่อมโยงผู้ให้รีวิว (`userId`), ร้านค้า (`storeId`), ไรเดอร์ (`riderId`), และออเดอร์ (`orderId`)

โครงสร้างนี้ช่วยให้นักศึกษาเรียนรู้การออกแบบฐานข้อมูลเชิงสัมพันธ์ระดับมืออาชีพ, การสร้าง Foreign Key เชื่อมโยงหลายบทบาท, การกำหนดสิทธิ์ด้วย **Row Level Security (RLS)** และการรักษาความถูกต้องสมบูรณ์ของข้อมูลระหว่างกระบวนการซื้อขายและจัดส่ง

Store Dashboard  
<div align="center">↓</div>  
Add Product Form (ระบุชื่อ หมวด ราคาปกติ ราคาพิเศษ วันหมดอายุ)

<div align="center">↓</div>  
ตรวจสอบสิทธิ์ร้านค้า (Store Role Verification)  
<div align="center">↓</div>  
บันทึกข้อมูลสินค้าลงตาราง `products` ใน Supabase Database  
<div align="center">↓</div>

### 7.2 ผู้บริโภคค้นหาสินค้า
Search & Filter Form  
<div align="center">↓</div>  
รับคำค้นหา (Keyword), หมวดหมู่, และพิกัดระยะทาง  
<div align="center">↓</div>  
Query ข้อมูลจากตาราง `products` เชื่อมกับ `stores` ใน Supabase  
<div align="center">↓</div>  
กรองเฉพาะสินค้าที่มี `status = 'active'` และมีจำนวนสินค้า `quantity > 0`  
<div align="center">↓</div>  
แสดงผลลัพธ์เป็น Product Cards พร้อมข้อมูลส่วนลดและระยะเวลาหมดอายุ  

---

### 7.3 ผู้บริโภคทำรายการสั่งซื้อ (Order Placement)
ผู้บริโภคเลือกสินค้าและระบุจำนวน  
<div align="center">↓</div>  
ตรวจสอบ Session และสิทธิ์บทบาท `consumer`  
<div align="center">↓</div>  
**เลือกรูปแบบการรับสินค้า:**  
- กรณีเลือก **Self-Pickup (รับเองที่ร้าน):** กำหนด `deliveryType = 'pickup'`, ค่าจัดส่ง = 0  
- กรณีเลือก **Rider Delivery (ให้ไรเดอร์จัดส่ง):** กำหนด `deliveryType = 'delivery'`, ระบุที่อยู่จัดส่ง และคำนวณค่าส่ง  
<div align="center">↓</div>  
ตรวจสอบจำนวนสต็อกคงเหลือในฐานข้อมูล  
<div align="center">↓</div>  
สร้างระเบียนใหม่ในตาราง `orders` สถานะเริ่มต้นเป็น `pending`  
<div align="center">↓</div>  
หักจำนวนสต็อกสินค้าในตาราง `products`  
<div align="center">↓</div>  
แจ้งเตือนไปยัง Store Dashboard ของร้านค้า  

---

### 7.4 ร้านค้ายืนยันและเตรียมสินค้า

<div align="center">↓</div>

<div align="center">↓</div>

เมื่อเตรียมเสร็จ ร้านค้ากดเปลี่ยนสถานะเป็น `ready` (Ready for Pickup)  
<div align="center">↓</div>  
- หากเป็นออเดอร์ **Self-Pickup:** ระบบแจ้งเตือนให้ผู้บริโภคเดินทางมารับสินค้าที่ร้าน  
- หากเป็นออเดอร์ **Rider Delivery:** ออเดอร์จะถูกส่งเข้า Delivery Job Pool ให้ไรเดอร์ในพื้นที่ทันที  

---

### 7.5 การจัดส่งสินค้าโดยไรเดอร์ (Rider Delivery Flow)
ออเดอร์พร้อมส่งปรากฏใน Delivery Job Pool ของไรเดอร์ในพื้นที่ใกล้เคียง  
<div align="center">↓</div>  
ไรเดอร์ตรวจสอบจุดรับของ (ร้านค้า), จุดส่งของ (ผู้บริโภค) และค่ารอบจัดส่ง  
<div align="center">↓</div>  
ไรเดอร์กดรับงานจัดส่ง (Accept Job)  
<div align="center">↓</div>  
ระบบอัปเดตสถานะออเดอร์เป็น `rider_assigned` พร้อมบันทึก `riderId = auth.uid()`  
<div align="center">↓</div>  
ไรเดอร์เดินทางไปร้านค้า และตรวจสอบความถูกต้องของสินค้า  
<div align="center">↓</div>  
ร้านค้าส่งมอบสินค้า ไรเดอร์กดยืนยันการรับสินค้า สถานะเปลี่ยนเป็น `picked_up`  
<div align="center">↓</div>  
ไรเดอร์เดินทางนำส่งสินค้าไปยังที่อยู่ของผู้บริโภค สถานะเปลี่ยนเป็น `delivering`  
<div align="center">↓</div>  
ไรเดอร์ส่งมอบสินค้าแก่ผู้บริโภค และกดยืนยันส่งสำเร็จ (`delivered`)  
<div align="center">↓</div>  
ระบบปรับสถานะออเดอร์เป็น `completed` บันทึกค่าตอบแทนให้ไรเดอร์ และแจ้งเตือนให้ผู้บริโภครีวิว

## 8. ตัวอย่าง Row Level Security (RLS) / Authorization ใน Supabase

SecondServe ใช้ **Supabase Auth** ร่วมกับ **PostgreSQL Row Level Security (RLS Policies)** เพื่อบังคับใช้นโยบายความปลอดภัยและการเข้าถึงข้อมูลในระดับแถวอย่างเข้มงวดตาม 4 บทบาท:

#### 1. การดูสินค้า (Public / Consumers)
- ผู้ใช้งานทั่วไปและผู้บริโภคสามารถอ่านข้อมูลสินค้าได้เฉพาะรายการที่มี `status = 'active'` และมี `quantity > 0`
- คำสั่งเชิงนโยบายตัวอย่าง:
  ```sql
  CREATE POLICY "Public read active products" 
  ON products FOR SELECT 
  USING (status = 'active' AND quantity > 0);
  ```

#### 2. การจัดการสินค้าของร้านค้า (`store`)
- เฉพาะผู้ใช้ที่มีบทบาท `store` เท่านั้นที่สามารถเพิ่มสินค้าได้
- สามารถแก้ไขหรือลบสินค้าได้เฉพาะรายการที่ `storeId` ตรงกับร้านค้าที่ผู้ใช้เป็นเจ้าของ (`ownerId = auth.uid()`)
  ```sql
  CREATE POLICY "Stores manage own products" 
  ON products FOR ALL 
  USING (storeId IN (SELECT id FROM stores WHERE ownerId = auth.uid()));
  ```

#### 3. การเข้าถึงคำสั่งซื้อของผู้บริโภค (`consumer`)
- ผู้บริโภคสามารถดูและตรวจสอบได้เฉพาะคำสั่งซื้อที่ตนเองเป็นผู้สั่ง (`userId = auth.uid()`)
  ```sql
  CREATE POLICY "Consumers view own orders" 
  ON orders FOR SELECT 
  USING (userId = auth.uid());
  ```

#### 4. การเข้าถึงคำสั่งซื้อของร้านค้า (`store`)
- ร้านค้าสามารถดูและอัปเดตสถานะออเดอร์ได้เฉพาะคำสั่งซื้อที่ส่งมายังร้านของตนเอง
  ```sql
  CREATE POLICY "Stores view own shop orders" 
  ON orders FOR ALL 
  USING (storeId IN (SELECT id FROM stores WHERE ownerId = auth.uid()));
  ```

#### 5. การดูและรับงานจัดส่งของไรเดอร์ (`rider`)
- ไรเดอร์ที่มีบทบาท `rider` สามารถดูออเดอร์ที่ต้องการจัดส่ง (`deliveryType = 'delivery'`) และอยู่ในสถานะพร้อมจัดส่งที่ยังไม่มีผู้รับ (`riderId IS NULL` และ `status = 'ready'`)
- ไรเดอร์สามารถอัปเดตสถานะการจัดส่งได้เฉพาะออเดอร์ที่ตนเองเป็นผู้รับมอบหมาย (`riderId = auth.uid()`)
  ```sql
  CREATE POLICY "Riders view available jobs" 
  ON orders FOR SELECT 
  TO authenticated 
  USING (
    (deliveryType = 'delivery' AND status = 'ready' AND riderId IS NULL)
    OR (riderId = auth.uid())
  );

  CREATE POLICY "Riders update assigned orders" 
  ON orders FOR UPDATE 
  USING (riderId = auth.uid() OR (riderId IS NULL AND status = 'ready'));
  ```

#### 6. การเข้าถึงข้อมูลที่อยู่และเบอร์ติดต่อสำหรับการจัดส่ง
- ที่อยู่จัดส่งและเบอร์โทรติดต่อจะเปิดเผยให้ไรเดอร์เห็นเฉพาะในระหว่างที่ไรเดอร์ปฏิบัติงานในออเดอร์นั้นๆ เพื่อปกป้องความเป็นส่วนตัวของข้อมูลผู้บริโภค (Data Privacy)

#### 7. การบริหารจัดการของผู้ดูแลระบบ (`admin`)
- ผู้ใช้ที่มีบทบาท `admin` (`auth.jwt() ->> 'role' = 'admin'`) มีสิทธิ์ตรวจสอบและดูแลข้อมูลทั้งหมดในระบบเพื่อความปลอดภัยและการดำเนินงานที่ราบรื่น

## 9. สรุป Project

SecondServe เป็นโครงงานและสตาร์ตอัปที่ผสานแนวคิดทางธุรกิจเพื่อสังคม (Social Enterprise / Sustainability) เข้ากับการพัฒนา Full-Stack Web Application ยุคใหม่ได้อย่างลงตัว โดยครอบคลุมทั้ง:

1. **เข้าใจปัญหาและสร้างคุณค่าชัดเจน:** แก้ปัญหา Food Waste ของร้านค้า และช่วยผู้บริโภคประหยัดค่าครองชีพ
2. **ระบบ 4 บทบาทผู้ใช้งานที่สมบูรณ์แบบ:**
   - **`consumer` (ผู้บริโภค):** ค้นหา เลือกซื้อ และเลือกรับของได้ทั้งรับเองหรือจัดส่ง
   - **`store` (ร้านค้า):** จัดการสต็อกสินค้าใกล้หมดอายุและคำสั่งซื้อ
   - **`rider` (ผู้ส่งสินค้า):** ให้บริการจัดส่งถึงที่และสร้างรายได้เสริมที่ยืดหยุ่น
   - **`admin` (ผู้ดูแลระบบ):** ควบคุมและดูแลความเรียบร้อยของระบบ
3. **โมเดลการดำเนินการที่ยืดหยุ่น:** รองรับทั้งการไปรับเองหน้าร้าน (Self-Pickup) และบริการจัดส่งในชุมชน (On-demand Delivery)
4. **สถาปัตยกรรมฐานข้อมูลที่มั่นคงด้วย Supabase (PostgreSQL):**
   - ฐานข้อมูลเชิงสัมพันธ์แบบ Relational เชื่อมโยงตารางผ่าน Foreign Keys
   - ระบบยืนยันตัวตนและการคุ้มครองข้อมูลด้วย Row Level Security (RLS)
   - จัดเก็บรูปภาพอย่างปลอดภัยบน Supabase Storage
5. **ความพร้อมในการพัฒนาเป็น Startup MVP:** มี Business Flow และ Data Flow ชัดเจน สามารถพัฒนาและส่งมอบโครงงานได้อย่างรวดเร็ว

#### ขอบเขตการต่อยอดในอนาคต
- ระบบจับคู่งานจัดส่งให้ไรเดอร์อัตโนมัติ (Smart Dispatching Algorithm)
- ระบบคำนวณเส้นทางจัดส่งสินค้าหลายจุดพร้อมกัน (Multi-stop Route Optimization)
- ระบบกระเป๋าเงินอิเล็กทรอนิกส์ (In-app Wallet) สำหรับตัดรอบรายได้ของร้านค้าและไรเดอร์
- ระบบแจ้งเตือนสินค้าใกล้หมดอายุผ่าน Line Notify หรือ Push Notifications
- พัฒนาต่อยอดเป็น Progressive Web App (PWA) หรือ Mobile Application สำหรับไรเดอร์และผู้บริโภค
